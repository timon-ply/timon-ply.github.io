# Timon Polley: public legal and support site

This public repository powers [timonply.com](https://timonply.com), the legal-document and support site for Timon Polley applications. GitHub Pages serves the `main` branch with the domain declared in `CNAME`.

The website remains public. It contains app documentation, support routes, website privacy notices, legal notices and `app-ads.txt`. Executable app previews, Android downloads and app backend source are maintained separately; this repository is not an application hosting workspace.

## Public content

- `index.html`: application and document chooser for NeonRoutine, Kalvenda and Exactake, including existing store links.
- `support.html`: support, privacy requests, accessibility feedback and safety reporting.
- `debug.html`: legal-route QA page.
- `neonroutine/`, `kalvenda/`, `exactake/`, `flatnest/`: existing app legal documents.
- `wunschkiste/`: retained legal/help pages for existing users; no executable app or downloads.
- `privacy.*.md` and `impressum.*.md`: website privacy and legal notices.
- `assets/` and `_layouts/`: shared site presentation and legal-page layout.
- `docs/regulatory-review.md`: engineering review notes.

Existing Flatnest legal documents remain available for compatibility, although Flatnest is not featured on the homepage. Review those documents against the rebuilt application before any launch. The presence of a document does not establish that an application feature has shipped or received legal review.

Documents cover German, English, Spanish and Japanese; NeonRoutine also has French documents. Canonical app URLs use `/app/document.language/`, with generated `.html` and `.md` aliases where configured. Keep existing app-store legal links stable.

## Source and generation

Most legal documents are generated by `tools/generate_legal_docs.mjs`. Update the generator when changing generated legal wording, language variants or route aliases, then regenerate:

```sh
node tools/generate_legal_docs.mjs
node --test tests/site-structure.test.mjs
```

Use Node.js 22 or newer. Run the generator twice and confirm the second run produces no additional changes. Legal wording needs human legal review; structural tests only check repository contracts and route consistency.

GitHub Pages uses Jekyll and `jekyll-redirect-from`, configured in `_config.yml`. Do not add a redirect alias that normalizes to the canonical page output path.

## Local review

For the static homepage, support page and assets:

```sh
python -m http.server 4173 --bind 127.0.0.1
```

Open `http://127.0.0.1:4173/`. A plain static server does not render Jekyll legal templates or redirect aliases; use a Jekyll/Pages build to verify those rendered routes. After a release, check canonical public URLs and aliases on the deployed site.

For presentation changes, review phone and desktop rendering, language selectors, document links, keyboard focus and narrow-screen overflow. Shared frontend assets are same-origin; the site does not load third-party fonts, analytics or advertising scripts.

## Remote development

`remote/project.yaml` and `scripts/remote/` describe the existing bootstrap, doctor, verification and preview commands. Screenshot/log output belongs in ignored `.remote-artifacts/`. Keep credentials, private app source and user data outside this public repository.

Publishing updates to `main` can update the public Pages site. Deployment is a separate action from local verification and must follow the current task's authorization. No application backend, store release or paid service should be started as part of legal-site maintenance.
